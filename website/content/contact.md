# Contact

Prune is an open-source project, so most conversations happen in public where others can benefit from them.

## Bugs, false positives and feature requests

Open an issue on GitHub: https://github.com/dlabadini/prune/issues

For a false positive, the most useful report includes a minimal repro: the smallest set of files that produces the wrong finding, the output of `prune scan --json` for it, and what you expected instead. Reports like that usually become a labeled fixture in the accuracy suite, so the fix stays fixed.

## Questions and ideas

Open an issue for those too. If you're not sure whether something is a bug, file it anyway. "Prune said X, I expected Y" is a perfectly good issue.

## Security

To report a security problem, email hello@prune.dev instead of opening a public issue. Please include steps to reproduce and the affected version (`prune --version`). You'll get an acknowledgement, and a fix will be coordinated before anything is disclosed.

## Everything else

Email hello@prune.dev for anything that doesn't fit an issue: partnerships, talks, press, or just telling us how Prune worked out in your codebase.
