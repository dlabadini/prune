why prune

Linters check each line. Agents make a mess across files.

Every line an agent writes can pass lint and typecheck while the codebase quietly grows a second User type, a helper nobody calls, and a file nothing imports. Prune reads the whole module graph, so it sees those problems.

eslint, tsc, biome

  • Unused variables inside a file
  • Type errors and syntax
  • Style and formatting
  • One file at a time

prune

  • Exports nothing reachable imports, through barrels and namespaces
  • Files no entry point reaches
  • The same shape declared under five names
  • God files, runtime import cycles, near-duplicate functions

pre-commit framework

The prune hook uses the binary on your PATH. prune-cargo builds from source instead.

Record existing debt once with prune baseline and commit .prune-baseline.json.

# .pre-commit-config.yaml
repos:
  - repo: https://github.com/dlabadini/prune
    rev: v0.2.0
    hooks:
      - id: prune
        args: [--fail-on, medium]

husky or lefthook

Install it per repo with npm i -D prunecode, like any other lint tool. With no arguments it checks staged files. Pass a file list to check only those.

# .husky/pre-commit
npx prune check
# lefthook.yml
pre-commit:
  commands:
    prune:
      glob: "*.{ts,tsx,js,jsx}"
      run: npx prune check {staged_files}

GitHub Actions

--baseline --ci exits 1 on any finding missing from the committed baseline. Add --changed origin/main to scope to the branch.

# .github/workflows/prune.yml
name: prune
on: pull_request
jobs:
  prune:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: curl -fsSL https://prunecode.ai/install.sh | bash
      - run: ~/.prune/bin/prune scan --baseline --ci

MCP server

prune mcp serves tasks, scan, plan, verify, who_uses, safe_to_delete, rename_impact and more over stdio.

# Claude Code
claude mcp add prune -- prune mcp
// .mcp.json · .cursor/mcp.json
{ "mcpServers": { "prune": { "command": "prune", "args": ["mcp"] } } }

Agent instructions

Two lines in AGENTS.md or CLAUDE.md keep agents from deleting something that's still used, and from leaving dead code behind.

Before deleting or renaming an export, ask Prune
(`safe_to_delete`, `rename_impact`).
After a refactor, run `prune check --fail-on medium`
and fix what it reports.

how it works

Prune marks. Your agent cuts. Prune checks the cut.

Prune never rewrites your code behind your back. It finds the dead wood, writes a precise task, and verifies the result, so an agent can clean up without guessing.

reachability

Not just "unused". How far from used.

Prune walks the graph twice, once from product entries and once from tests. It resolves imports through barrels, aliased re-exports, namespaces and Convex references, then gives every export exactly one class.

local-first

Your code never leaves the shed.

Prune is a single Rust binary. Parsing (Oxc), structural matching (ast-grep) and the index (SQLite) all run on your machine. Semantic matching uses a small local embedding model, and only once you've downloaded it.

  • No account, no telemetry, no network calls during a scan
  • Next.js and Convex adapters find framework entries for you
  • Fenced boundaries let a package keep its own types on purpose
  • An accuracy harness with labeled fixtures guards precision in CI
0bytes of code sent anywhere
100%precision & recall on labeled fixtures
1binary: no runtime, no account, no config needed
MITfree for any use, forever
